# 04. Architecture

This is the shape that worked end to end on the simulator. Rebuild it from scratch at the event.

## Components

```
[G2 glasses] <-Bluetooth-> [Even Realities phone app, hosting our WebView app]
                                   |
                       WebSocket (PCM audio up; cards, recap down)
                                   |
                     [Server: Node + TypeScript]
                      - streaming speech-to-text (behind one small interface)
                      - term matcher + card rules (no LLM)
                      - wearer detection by loudness
                      - rolling in-memory transcript + "lost" markers
                      - Gemini: agent, "used correctly?" check, recap
                      - small persistent store (approved terms, learned ids, recaps)
                                   |
                              REST (+ optional live socket)
                                   |
                     [Companion: mobile-first web app (Next.js works)]
```

| Part | Tech that worked |
|---|---|
| Glasses app | Vite + TypeScript + `@evenrealities/even_hub_sdk` (0.0.16 was current). Start from Even's public `asr` template. |
| Server | Node 24 + TypeScript (run with tsx), `ws`, `@google/genai`, Deepgram nova-3 live streaming, `@sentry/node` |
| Companion | Next.js (App Router) + `@sentry/nextjs` (tracing + Session Replay) |
| Storage | A JSON file on the server was enough. Supabase is optional (adds a live view via Realtime) but isn't a sponsor here; don't add it unless the live view is needed. |

## Design rules (enforce in code)

- **No LLM in the card path.** Cards come from plain string matching on the transcript: term, aliases, and
  simple inflections (fold → folds/folded/folding). Matching costs about 0.03 ms; a card reached the display
  2–9 ms after a sentence. A Gemini call before each card would add 0.6–2.8 s normally and 6–8 s on a stall.
- **Match on interim results** so a card can appear before the sentence ends (measured 0.2–2 s from the spoken
  word to the card, speech-to-text included). Log held-back cards on finals.
- **One card on screen, one new card per ~30 s, same term not within ~2 min, confidence floor ~0.6.**
- **Never store audio.** Transcripts in memory only, wiped when the session ends.
- **Only approved terms reach the glasses.** Approval is the only code path that makes a term live. Keep
  proposals out of the persistent store until approved.
- **Speech-to-text behind one small interface** so switching Deepgram to ElevenLabs Scribe is a one-file change.
  Benchmarks take the provider as a parameter.
- **Every LLM call has a timeout and a fallback chain** (see [05](05-LESSONS.md)).
- **API keys stay on the server.** Even's `asr` template puts the speech key in the WebView bundle; don't do that.
  Stream audio to our server instead.

## Term matching

Do **not** train a model for term matching. It is unlikely to beat string matching with aliases, and it would
cost hours of the 36:
- The matcher isn't the weak point. In noise the words never reach the transcript correctly, so a model that
  reads the transcript can't find them either.
- There's no training data. Each company's jargon is different and is built at the event, so you would have to
  label example sentences for every term and retrain whenever a term is approved.
- Spotting words directly in the audio (the way wake-word models work) needs recordings of every term, which
  doesn't fit a jargon pack that changes per company.

Instead, match in layers, all fast enough to keep cards instant (well under a millisecond per sentence):
1. **Exact match** on the term, its aliases and simple inflections.
2. **Aliases generated by Gemini when the pack is built** (spoken forms, acronym spellings, likely mishearings),
   shown on the review card so the human can remove bad ones. Never at card time.
3. **Sound-alike matching.** Convert each term, and each run of 1 to 3 transcript words, to a Double Metaphone
   sound code, and compare spellings by edit distance. This catches mishearings like "cube cuddle" for
   "kubectl". About an hour to build. Only accept a sound-alike match for terms of 6+ letters or multi-word
   terms, so short everyday words don't spam cards.
4. **Embeddings are optional and never gate a card.** They match meaning, not sound, so they don't fix
   mishearings, and they add wrong cards. Use them only to spot someone describing a term without saying it,
   in the scan after the meeting.

**Prove it:** run the crowd-noise test set through (a) plain matching, (b) + aliases, (c) + sound-alike, and
count terms caught and false cards for each. That number belongs in the Sentry and Gemini write-ups.

## Where Gemini is used

| Job | When | Model choice |
|---|---|---|
| Jargon-pack agent (function calling) | Async, user-triggered in the companion | Lite model first, larger as fallback; output is verified anyway |
| Alias and mishearing list per term | Async, when the pack is built (also fed to Deepgram keyterms) | Lite |
| "Used it correctly?" check | Live, after the wearer says an unlearned term | Lite chain, short timeout |
| "I'm lost" recap | After the conversation goes quiet | Lite chain, short timeout |
| Ambiguous-term refinement, post-meeting "missed terms" scan | Optional, async | Lite |

Never gate a card on Gemini. If a term is ambiguous, show the card and refine afterwards.

## Wearer detection

Speaker labels from diarization drift (the wearer's label changed mid-session in testing, and another voice got
the wearer's label). Use **loudness** instead: the G2 mic is on the wearer's head. At session start the wearer
says a fixed phrase ("start listening") to calibrate. Keep a rolling audio window (about 2 minutes) in a
**fixed-size ring buffer**, measure RMS under each matched word, and treat it as the wearer if it is at least
~50% of the calibration loudness. Diarization is only a fallback. The real near/far ratio on G2 is HW-PENDING.

## Session lifecycle

- One session per glasses connection. The glasses app reconnects with backoff and re-enables the mic on the
  foreground event (Android may suspend the WebView).
- If the speech-to-text stream closes mid-session, **reopen it with backoff** and keep a running sample offset
  so the loudness lookup stays aligned. (A dropped stream once left a session silently deaf.)
- On server start, close any sessions left open by a crash.
- Terms approved mid-session apply immediately (rebuild the matcher on change).
- End of conversation = ~20 s of quiet or app exit → recap if a marker exists.

## Data model (minimal)

- **Term:** id, term, aliases (including likely misspellings from speech-to-text), definition (≤ ~110 chars),
  source document, exact quote, confidence, "why jargon", status (proposed / not sure / approved / rejected),
  edited-by-user flag.
- **User term state:** seen count, dismiss count, learned, learned via (spoken / gesture), learned at.
- **Session:** start, end, recap text, terms shown. No audio, no stored transcript.
- Glasses keep learned ids in **SDK storage** too, so the display can skip learned terms immediately.

## Hosting

A Beta build's `app.json` must whitelist the server's exact `https://` and `wss://` host **at pack time**, so the
host must be stable. Options that worked:
- **Tailscale Funnel** from a laptop: free, a fixed `https://<machine>.<tailnet>.ts.net` URL that survives
  restarts. The laptop must stay awake and online. This passed: same URL after restart, 5 min of 16 kHz audio
  with no lost frames (p95 frame gap ~100 ms), hosted card latency p50 7 ms / p95 22 ms over 20 sentences, and
  it worked over a phone hotspot.
- A small VPS with Caddy for automatic TLS; `<ip-with-dashes>.sslip.io` gives a hostname without a domain.
  Not tested end to end.
- Cloudflare **quick** tunnels change URL every run: not usable for a Beta build. If used for a quick test on a
  network that blocks QUIC, force `--protocol http2`.

A public host needs protection: a shared token on the API and sockets (it ships in client bundles, so it only
keeps strangers out), a separate token on any debug routes, and no debug mode on the public host unless the
debug routes are token-protected. Any endpoint that runs the agent spends Gemini quota.
